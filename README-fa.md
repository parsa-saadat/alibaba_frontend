# ژئو کالا — فرانت‌اند بازارگاه تجهیزات نقشه‌برداری

React 19 + Vite 7 + Tailwind 4 · رابط فارسی و راست‌به‌چپ · تم تاریک/روشن

## اجرا

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # ساخت نسخه‌ی نهایی در dist/
npm run preview
```

## شروع سریع (روی سیستم خودتان، همراه بک‌اند پورت ۳۰۰۰)

پیش‌نیاز: Node.js نسخه‌ی ۱۸ یا بالاتر (`node -v`). اگر بک‌اند شما روی
`http://localhost:3000` بالا است، فقط همین سه خط:

```bash
cd frontend
npm install
npm run dev
```

بعد در مرورگر **http://localhost:5173** را باز کنید. همین. فرانت همه‌ی درخواست‌ها را
به `/api/...` می‌فرستد و ویت آن‌ها را به `http://localhost:3000` بک‌اند خودتان
پروکسی می‌کند (بدون CORS، بدون تنظیم اضافه).

> **مهم:** سایت را از دامنه/پیش‌نمایش ابری باز نکنید؛ سرور ابری به `localhost`
> کامپیوتر شما دسترسی ندارد. آدرسی که در نوار مرورگر باید باشد همان
> `http://localhost:5173` است.

### اگر بک‌اند روی پورت/آدرس دیگری است

```bash
# macOS / Linux
API_PROXY_TARGET=http://localhost:4000 npm run dev

# Windows PowerShell
$env:API_PROXY_TARGET="http://localhost:4000"; npm run dev

# Windows CMD
set API_PROXY_TARGET=http://localhost:4000 && npm run dev
```

### عیب‌یابی سریع

| نشانه | علت | راه‌حل |
| --- | --- | --- |
| صفحه بالا می‌آید ولی محصولی نیست / «خطا در دریافت محصولات» | بک‌اند روی ۳۰۰۰ بالا نیست | بک‌اند را اجرا کنید؛ سپس `curl http://localhost:3000/product?limit=1` باید JSON بدهد |
| `Port 5173 is already in use` | نمونه‌ی دیگری از ویت باز است | آن را ببندید یا `npx vite --port 5174` |
| `ECONNREFUSED ::1:3000` یا `ECONNREFUSED 127.0.0.1:3000` در ترمینال ویت | بک‌اند روی همان خانواده‌ی آدرس `localhost` گوش نمی‌دهد | `API_PROXY_TARGET=http://127.0.0.1:3000 npm run dev` (یا `http://[::1]:3000`) |
| بعد از تغییرات، رفتار قدیمی می‌بینید | کش وابستگی‌ها | `rm -rf node_modules/.vite` و سپس `Ctrl+Shift+R` |
| بیلد نهایی می‌خواهید | — | `npm run build` → خروجی تک‌فایل در `dist/index.html` |

## صفحه‌های قوانین

| مسیر | مخاطب | موضوع |
| --- | --- | --- |
| `/terms/customers` | مشتریان (همه‌ی کاربران) | حساب کاربری، محتوا، نظرات، حریم خصوصی، تعهد پشتیبانی |
| `/terms/buyers` | خریداران | ثبت سفارش، پرداخت، ارسال، بازگشت کالا، گارانتی |
| `/terms/sellers` | فروشندگان | احراز هویت، پلن و کمیسیون، تسویه، ممنوعیت‌ها |

هر سه صفحه با یک قالب مشترک (`components/legal/LegalPageComponent`) و تب جابه‌جایی نمایش داده می‌شوند؛
متن‌ها در `src/pages/main/TermsPage.jsx` است و ویرایش آن‌ها فقط همان‌جا لازم است.

## نکته‌های طراحی که در کد پیاده شده‌اند

- **هدر:** شعار زیر لوگو حذف شده و لوگو بزرگ‌تر است (موبایل ۳۶px، تبلت ۴۰px، دسکتاپ ۴۸px).
- **ارتفاع هدر در متغیر `--header-h`:** هر جزء چسبان (سرستون جدول مقایسه، نوار ابزار ویرایشگر، ستون‌های کنارِ چسبان) از همان استفاده می‌کند تا هیچ‌وقت زیر هدر پنهان نشود.
- **گرید «پیشنهاد برای شما»:** حداکثر ۴ ردیف (`MAX_ROWS` در `InfiniteProductsComponent`).
- **نوار اقدام محصول:** کارت «قیمت + افزودن به سبد خرید + ارتباط با فروشنده» داخل ستون چسبانِ کنار
  «مشخصات فنی» است و همراه صفحه اسکرول می‌شود؛ هیچ نواری به پایین دسکتاپ چسبیده نیست.
- **محو‌شدگی دو سرِ اسکرول:** کلاس `scroll-fade-x` فقط وقتی اعمال می‌شود که ردیف واقعاً سرریز داشته باشد
  (`hooks/useScrollFade.js`)؛ بنابراین اولین و آخرین لینک نوار منو دیگر سایه/محو‌شدگی ندارد.
- **جدول مقایسه:** سرستون‌ها فقط در لپ‌تاپ/دسکتاپ چسبان‌اند (`lg:sticky`)؛ در موبایل با اسکرول افقی
  همراه می‌شوند. عنوان هر گروه دقیقاً ۱px زیر سرستون می‌نشیند (`--cmp-head`) و بعد از پایان گروه،
  گروه بعدی جایش را می‌گیرد.
- **ویرایش محصول (پنل):** نوار بالای فرم به بالاترین نقطه می‌چسبد و ارتفاعش در `--editor-bar-h` ذخیره
  می‌شود؛ نوار ابزار ویرایشگر و «پنل پیشرفته‌ی جدول» هر دو یک بلوک چسبان‌اند و پنل جدول دقیقاً زیر
  نوار ابزار می‌آید (بدون اورلی و بدون `fixed`).
- **هدر صفحه‌های پنل:** همه‌ی تب‌های ادمین و فروشنده از `components/panel/PanelPageHeaderComponent`
  استفاده می‌کنند (آیکن در کادر زرد، عنوان، توضیح، دکمه‌ی «به‌روزرسانی») تا یک تم واحد داشته باشند.
- **متغیر `--header-h` در پنل:** چون پنل هدر سایت را ندارد، داخل `.admin-wrapper` (ادمین و فروشنده)
  بازنویسی می‌شود: `0px` در دسکتاپ و `60px` در موبایل (ارتفاع نوار بالای پنل).
- **پاپ‌آپ نشانی:** `components/address/AddressFormModalComponent` — هم ثبت و هم **ویرایش** نشانی در
  پاپ‌آپ انجام می‌شود (`addressId` + `initial`)؛ فرم درون‌صفحه‌ای وجود ندارد.
- **بوردرها:** پیش‌فرض رنگ بوردر در `@layer base` روی `var(--border)` تنظیم شده تا هیچ‌جا خط مشکی/سفید خالص نماند.
- **تم روشن:** خاکستری‌ها خنثی‌اند (`#f3f3f5`، `#ececee`، `#5c5e66`) و مایل به آبی نیستند.

## داده‌ی آزمایشی (Mock)

برای تست سریع بدون وارد کردن دستی داده، در پوشه‌ی بک‌اند (`alibaba_backend`) اجرا کنید:

```bash
npm run seed:mock            # درج داده‌ی نمونه
npm run seed:mock -- --reset # پاک‌سازی و درج دوباره
```

کاربران نمونه برای ورود با OTP (با `STATUS=DEV` کد تأیید در پاسخ API برمی‌گردد):
`09120000001` (مدیر)، `09120000002` و `09120000003` (فروشنده)، `09120000004` (خریدار).
جزئیات کامل در `alibaba_backend/README.md`.

## اتصال به API

آدرس API در کد **نسبی** است: `/api`.

- `vite.config.ts` یک پروکسی دارد که `/api/*` را به بک‌اند روی پورت ۳۰۰۰ می‌فرستد
  (`http://localhost:3000`) و پیشوند `/api` را حذف می‌کند؛ یعنی
  `/api/product` ← `http://localhost:3000/product`.
- پس مرورگر فقط با همان دامنه‌ای که سایت را باز کرده حرف می‌زند؛ نه خطای CORS، نه
  نیاز به دسترسی مرورگر به `localhost` (مشکل قبلی که هیچ بخشی به API وصل نمی‌شد).
- اگر بک‌اند جای دیگری است: `API_PROXY_TARGET=http://host:port npm run dev`.
- برای دیپلوی واقعی (بدون پروکسی ویت) آدرس کامل بدهید:
  `VITE_APP_API_URL=https://api.example.com npm run build`.

### خطای `Invalid hook call` یا `Cannot read properties of null (reading 'useState')`

یعنی مرورگر **دو نسخه از React** را هم‌زمان داشته (نسخه‌ی کش‌شده‌ی قدیمی + نسخه‌ی تازه‌ی
باندل‌شده) — نه باگ کد. سه لایه برای جلوگیری گذاشته شده است:

- `optimizeDeps.include` در `vite.config.ts`: React و دوستانش یک‌بار در شروع باندل می‌شوند،
  پس وسط سشن هش‌شان عوض نمی‌شود.
- `resolve.dedupe`: فقط یک کپی از `react` / `react-dom` / `react-router-dom`.
- اسکریپت «ترمیم خودکار» در `index.html`: اگر این خطا دیده شود، صفحه یک‌بار خودش با
  آدرس تازه بارگذاری می‌شود (فقط یک‌بار برای هر تب تا حلقه نشود).

با این حال اگر بعد از آپدیت دیدید، یک‌بار **Ctrl+Shift+R** بزنید.

### خطای `does not provide an export named ...`

این خطا یعنی مرورگر نسخه‌ی **قدیمی یک ماژول** را از کش خوانده، در حالی که فایل جدید
خروجی تازه‌ای دارد (یا سرویس esbuild سرور dev از کار افتاده و ماژول ناقص سرو شده).
درمان:

```bash
# سرور dev را ببندید، سپس:
rm -rf node_modules/.vite
npm run dev
```
و در مرورگر **Ctrl+Shift+R**. برای اینکه دیگر تکرار نشود، در `vite.config.ts` هدر
`Cache-Control: no-store` برای حالت dev تنظیم شده و `ShopContext` هم دیگر به خروجی
جدیدِ `storage` وابسته نیست.

اگر بعد از تغییر پوشه یا آپدیت، بعضی صفحه‌ها سفید شدند: سرور dev را ببندید،
`node_modules/.vite` را پاک کنید و دوباره `npm run dev`؛ بعد در مرورگر **Ctrl+Shift+R**
(hard reload) بزنید تا ماژول‌های کش‌شده‌ی قدیمی دور ریخته شوند.
