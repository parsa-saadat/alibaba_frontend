# فرانت‌اند نسخهٔ ۱۴

## تغییرات
- فیلدهای چندزبانه در API با ساختار مستقل `name: { en, fa, ar, tr }` و به همین شکل در دیتابیس ثبت می‌شوند؛ description، brand و سایر فیلدهای محتوای چندزبانه هم همین الگو را دارند.
- فرم همچنان تب‌های چهار زبان را دارد و ورود محتوای محصول، فروشگاه، دسته‌بندی و پلن صرفاً دستی است.
- لایهٔ HTTP فیلدهای فرم را به آبجکت‌های مستقل تبدیل می‌کند. آبجکت قدیمی translations در درخواست جدید فرانت ارسال نمی‌شود. تبدیل سازگار داخلی فرم فقط در حافظه است، نه ذخیره در دیتابیس.
- خواندن پاسخ raw برای ویرایش، متن همهٔ زبان‌ها را حفظ می‌کند؛ خواندن نمایشی مطابق زبان انتخابی و fallback است.
- نام و نام خانوادگی کاربران و فروشنده‌ها با نویسه‌گردانی ساده و آفلاینِ بک‌اند تکمیل می‌شوند؛ هیچ API مترجم اضافه نشده است. املای دقیقِ دستی اولویت دارد و روش تقریبی جای املای تأییدشدهٔ شخص را نمی‌گیرد.
- فیلتر محصولات صفحهٔ فروشگاه بازطراحی شده است: جستجو و مرتب‌سازی با عرض مناسب، کلیدهای دارای وضعیت انتخاب، پاک‌کردن فیلترها، شمارندهٔ نتیجه و کنترل‌های لمسی حداقل حدود ۴۴ پیکسل. در موبایل فیلدها زیر هم و کلیدها در دو ستون قرار می‌گیرند؛ پهنای ثابتِ مشکل‌ساز حذف شده است.
- صفحهٔ مقایسه پاسخ‌های field-first را می‌خواند؛ نام محصول، برند و نام فروشگاه با زبان انتخابی نمایش داده می‌شوند و آبجکت به شکل [object Object] چاپ نمی‌شود.

## اجرا
```sh
npm ci
npm run dev
npm run build
node scripts/check-i18n.mjs
```
Node.js 20.19+ یا 22.12+ لازم است. API پیش‌فرض /api است و Vite به بک‌اند پورت 3000 پروکسی می‌کند. برای محیط استقرار reverse proxy متناسب را تنظیم کنید. env نمونه محرمانه نیست؛ env واقعی داخل بسته قرار ندارد.

## نصب همراه بک‌اند
این نسخه را با بک‌اند همین بسته نصب کنید. **برای دیتابیس قدیمی ابتدا دستور مهاجرتِ README بک‌اند را پس از پشتیبان‌گیری و توقف نوشتن برنامه اجرا کنید.** تغییر سورس به‌تنهایی سندهای فعلی سرور شما را تبدیل نمی‌کند.

راهنمای کوتاه:
```sh
# داخل backend، فقط پیش‌نمایش؛ source زبان متن پایهٔ قدیمی است
npm run migrate:i18n -- --source=fa
# پس از بررسی، پشتیبان و توقف نوشتن برنامه
npm run migrate:i18n -- --source=fa --apply --backup-confirmed
```
اگر conflicts غیرصفر است، آن را بررسی و حل کنید؛ سند متعارض خودکار بازنویسی نمی‌شود. برای داده‌های مبنای مخلوط یک زبان را کورکورانه انتخاب نکنید. پس از مهاجرت، بک‌اند را restart و فرانت را build و مستقر کنید.

## امکانات حفظ‌شده
هدر جمع‌شونده با اسکرول، نوار زبان/ارز غیرsticky، لوگوی موبایل کنار منو، Markdown تمام‌صفحهٔ مستقل از سمت سایدبار، فونت و ارقام محلی، قواعد sentence case، قیمت کاتالوگ با ارز خودش و مبلغ سفارش/پرداخت با ریال قفل‌شده حفظ شده‌اند. تغییر مدل متن نباید به تبدیل دوبارهٔ مبلغ سفارش منجر شود. API ترجمهٔ محتوا، دکمهٔ ترجمهٔ خودکار یا تکمیل خودکار محصول هنگام ذخیره وجود ندارد.

## بررسی انجام‌شده
- مرورگر واقعی: ورود دو زبان در فرم، بررسی payload بدون translations، درخواست HTTP واقعی به بک‌اند و تأیید ساختار name.en/name.fa مستقیماً در MongoDB.
- ۱۶ حالت زبان/عرض برای فروشگاه و مقایسه: چهار زبان × عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۳۶۵؛ کنترل‌ها، فیلتر، پاک‌کردن، انتخاب مرتب‌سازی، چیدمان و نمایش متن از پاسخ آبجکتی بررسی شدند. دادهٔ API این بررسی‌های ظاهری mock بود.
- بک‌اند: ساخت/ویرایش فیلدهای محصول، فروشگاه، دسته‌بندی و پلن، پاک‌کردن یک زبان بدون تغییر بقیه، خواندن و جستجوی چندزبانه و نویسه‌گردانی نام روی MongoDB محلی بررسی شد.
- مهاجرت: پیش‌نمایش بدون نوشتن، تبدیل و حذف metadata قدیمی، حفظ قیمت/موجودی و مبلغ سفارش، اجرای مجدد بدون تغییر و رد تعارض بررسی شدند.

پرداخت واقعی، SMS و دیتابیس production کاربر در این محیط بررسی نشده‌اند. فایل‌های بررسی، عکس‌ها و گزارش‌ها، build و node_modules داخل ZIP نیستند؛ بک‌اند هم فایل یا وابستگی تست ندارد.
